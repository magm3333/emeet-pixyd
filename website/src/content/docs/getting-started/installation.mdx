emeet-pixyd runs on Linux (`amd64`, `arm64`, and Docker `arm/v7`) and requires an EMEET PIXY dual-camera AI webcam (USB `328f:00c0`) or PIXY 2K (`328f:0118`) — see [Supported Devices](/getting-started/supported-devices/) for the full compatibility matrix, including which other EMEET webcams are recognized.

## Prerequisites

- **Linux** (x86_64 or aarch64 for native installs; Docker also supports ARMv7) — the daemon uses Linux-specific APIs (`/proc`, netlink, V4L2, hidraw)
- **EMEET PIXY** webcam connected via USB
- **Go 1.27.1+** (only for building from source)

## Docker (amd64, arm64 and Raspberry Pi 3 arm/v7)

The fork publishes `magm3333/emeet-pixy-dual-cam` for `linux/amd64`,
`linux/arm64`, and `linux/arm/v7` (32-bit Raspberry Pi 3). On a Linux host with Docker Compose v2:

```bash
git clone https://github.com/magm3333/emeet-pixyd.git
cd emeet-pixyd
cp docker/.env.example docker/.env
# Edit docker/.env to match the host's video/hidraw paths, GIDs, and UID/GID.
mkdir -p docker/data
chown "$(id -u):$(id -g)" docker/data
docker compose --env-file docker/.env -f docker/compose.yaml pull
docker compose --env-file docker/.env -f docker/compose.yaml up -d --no-build
```

Open `http://<host-LAN-IP>:18090/` (for example, `http://raspi4:18090/`). Compose
publishes the unauthenticated API on all IPv4 interfaces, so restrict access to
a trusted LAN with the host firewall. State persists under `docker/data/`, and
the image defaults to manual mode because a private container `/proc` namespace
cannot detect host calls. Detailed device, build, architecture-test, and Docker
Hub publish instructions are in the fork's
[`docker/README.md`](https://github.com/magm3333/emeet-pixyd/blob/master/docker/README.md).

## NixOS (recommended)

Add the flake input and enable the module:

```nix
# flake.nix
inputs.emeet-pixyd.url = "github:magm3333/emeet-pixyd";

# In your nixosConfiguration:
inputs.emeet-pixyd.nixosModules.default
```

Then in your configuration:

```nix
hardware.emeet-pixy = {
  enable = true;
  auto = "full";           # off | full | tracking-only | privacy-only
  defaultAudio = "nc";     # nc | live | org
  debug = false;
};
```

That's it. The module installs:

- The daemon binary (`emeet-pixyd`)
- A CLI symlink (`emeet-pixy`)
- udev rules for PIXY hidraw + video4linux access
- A systemd user service (runs after PipeWire + graphical-session)
- All runtime dependencies in PATH (`v4l-utils`, `wireplumber`, `libnotify`)
- A tmpfiles.d entry for `/run/emeet-pixyd`

## Build from Source

```bash
git clone https://github.com/magm3333/emeet-pixyd.git
cd emeet-pixyd
nix build    # or: go build -o emeet-pixyd .
```

:::note[Building from source]
If building with `go build` directly, run `templ generate` first if you've modified any `.templ` files. The Nix build does this automatically.
:::

### Manual Dependencies

If not using the NixOS module, ensure these are in your `PATH`:

| Tool          | Purpose                           | Required            |
| ------------- | --------------------------------- | ------------------- |
| `v4l2-ctl`    | Pan/tilt/zoom control via V4L2    | Yes                 |
| `ffmpeg`      | MJPEG streaming in web UI         | For preview only    |
| `wpctl`       | PipeWire default source switching | For audio switching |
| `notify-send` | Desktop notifications             | Optional            |

## Verify Installation

Start the daemon:

```bash
emeet-pixyd
```

Check status:

```bash
emeet-pixy status
```

If the PIXY is connected, you should see camera state, audio mode, PTZ position, and auto mode.
